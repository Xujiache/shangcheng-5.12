## 二、本轮修复记录

### S01：统一页面框架与密度

- `SecondaryHeader` 使用生成图片返回图标、至少 44 vp 点击区域及可换行标题，顶部安全区只在标题组件计算。
- `SecondaryFeedback` 区分无权限、功能不可用和请求失败，提供重试；不会展示底层接口路径/堆栈。
- `SecondarySaveBar` 将业务设置的主操作固定在滚动区外，保留底部安全区和未保存提示。
- 调整相关卡片、字段和正文间距；佣金、价格规则、门店授权、店铺装修在 720 vp 及以上采用双列分区。
- 聊天、地图、协议和会员继续使用专用布局；装修中的缩略手机预览不是普通正文区域。

### S02：业务设置不再偷偷提交

- 佣金与价格规则移除编辑防抖自动保存及页面离开时提交。
- 首次加载成功才建立基线；明确点击保存才提交，失败保留当前草稿。
- 店铺装修与门店授权只保留一个固定主保存入口；保存成功才更新基线。
- 保存超时进入结果核对：仅重新读取服务端状态，不自动重发写请求；核对失败时阻止继续保存。
- 遗留无账号归属的价格规则缓存没有删除，但不会自动上传到当前账号。

### S03：授权、编辑和返回

- 门店申请先进入授权编辑页，查看等级、范围与有效期后明确保存，不再一点击就下发默认一年授权。
- 客户价格层级和价格访问权限增加对象及影响确认；原有黑名单、删除和离职确认保留。
- 员工权限编辑复制数组，取消不再可能污染列表中的原对象。
- 分类、员工、优惠券、佣金商品规则、售后、代理定价和厂家代理申请增加统一未保存退出确认。
- 页面返回、系统返回和编辑遮罩取消统一关闭当前弹层或询问是否放弃修改；保存中阻止再次提交。
- 商品筛选和完整经营数据的路由持有各自返回代理：先关闭筛选/日期说明弹层，不使用全局返回回调。
- 位置选择绑定发起页面的 token 和账号；其他编辑会话或账号的结果不能回填当前店铺资料。

### S04：异步状态和列表恢复

- `PageReadScope` 用页面生存期、独立请求通道、递增编号和账号上下文约束结果回写；不重试业务写操作。
- 切换筛选清除不属于新条件的列表；同条件刷新失败保留已有列表。客户、门店、售后与筛选订单分页失败保留已加载数据及页码。
- 客户、门店、广场及订单搜索采用 300 ms 防抖，搜索确认取消尚未触发的计时器，页面离开时清理。
- 广场可见范围改成独立草稿和明确保存；筛选重置仅改草稿，确认相同条件不重复请求。
- 售后写操作结果不明确时，后续确认转成只读核对，不自动再次执行同意或驳回。
- 相关远程缩略图复用现有失败重试组件，商品图片数组读取增加缺项保护。

### S05：兼容与类型

- 授权和优惠券使用独立业务日期合法性检查，允许未来日期，不套用统计页的未来日期/366 天限制。
- 保留主题、语言持久化与设置菜单自身的实时订阅机制；是否满足所有真机返回场景仍需设备验证。
- 错误分类接受 `Object` 并在边界收窄为 `ApiError`，避免 ArkTS 的结构类型转换问题；佣金对象映射有明确返回类型。
- 更新过期的源码断言，使其检查新的显式保存和既有更严格的商品/订单保护条件；没有删除业务断言或跳过测试。
