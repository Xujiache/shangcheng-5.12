## 修复内容

1. **多个请求重复刷新登录状态。** 三个 uni-app 端记录请求实际使用的 token；旧 token 的迟到失效响应复用已经刷新的 token，不再触发第二次刷新。保存新登录状态失败时使旧请求失效，避免继续回写旧会话。
2. **异常响应被错误处理。** 刷新服务返回 5xx 时保留登录状态，即使响应包含鉴权类错误码也不误清登录；缺少 `data` 的响应、非成功 HTTP 状态搭配成功业务码，不再被当成成功结果。
3. **刷新令牌可被并发重复使用。** 后端通过 Redis `SET NX EX` 原子消费令牌回执；旧版无 `jti` 的令牌使用哈希回执同样限制为一次。刷新时读取最新账号状态、角色和商家归属，停用账号不能刷新，也不延用旧权限快照。
4. **撤销服务失败仍可能放行。** 已配置 Redis 但连接或命令失败时返回可重试错误；生产缺少 Redis 不使用内存兜底。登出撤销失败不再报告成功。内存回执容量不足时不清空有效回执，连接恢复也不复用已完成的连接等待对象。
5. **错误提示与诊断信息不完整。** 参数校验数组转换为可显示文案；内部错误响应继续隐藏细节，受控日志保留过滤后的调用栈和追踪编号，不记录敏感异常正文。
6. **发布证据存在矛盾仍可能放行。** 证据中的命令退出码非零时，即使标记为通过也拒绝放行。
