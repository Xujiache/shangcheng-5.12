# ALIGNMENT / CONSENSUS

## 已确定范围

保留全部已有业务和技术框架；商城 shared 继续作为 TS 契约源，门窗利账原生实现独立，鸿蒙保留 ArkTS/ArkUI 及固定 IBest UI 子模块。首期单体部署，不引入微服务或 Kubernetes。

正式上线验收覆盖真实数据库、Android/iOS 微信、实际 App 安装包、鸿蒙手机/宽屏设备及支付、IAP、Push、短信、地图和云同步。外部阻塞不得删除或转换为模拟通过。

## 不变更边界

- 成功响应、`message/msg` 双字段、现有路由域、金额单位、状态值与分页结构保持兼容。
- 记工本机建档、记账、结算、付款、导出、备份免费；会员仅增加主动开启的云能力。到期保留本地与历史取回。
- 历史金额、ID、日期、单价快照不重算；工天/工时/件数不混加；不把工资自动计入订单人工成本。
- 游客与账号隔离；不清除普通缓存之外的台账、凭证及恢复日志。
- 不改用户本地 `project.config.json`，不重置数据库，不强推、不自动合并 main，不发布正式应用或执行真实付款。

## 决策记录

1. Node 固定 24.19.0（本机可验证的 24 LTS），pnpm 固定 9.0.0；不同时升级 Nest/Prisma/uni-app 大版本。
2. 采用独立的格式、语义 lint、类型、单元、集成及外部验收层。语义检查启用实际 correctness 规则；没有声称已消除全部 legacy any/unused-variable 技术债。
3. uni-app 条件编译分别检查 H5、MP-WEIXIN、APP-PLUS；保留路由文件命名，不为 lint 改路由。
4. 会话刷新抽到平台无关协调器；各端保存现有 key、公开请求 API 和命名空间守卫。只有协调器自身的 token 轮换维持会话 epoch；外部登录/退出使旧请求失效。
5. 写操作重新查询用户当前状态/归属；普通读仍有 60 秒缓存，不宣称所有场景即时吊销。数据库清空的商家关系不得从旧 token 补回。
6. 新增 live/ready，保留原 health。ready 检查数据库和正式环境必需的 Redis；MinIO/业务任务等更完整就绪检查仍列为后续任务。
7. 版本 SQL 从记工升级试点开始，advisory lock、事务、结构检查、校验和、显式 adopt；尚未宣称已为全历史 SQL 建立完整基线。
8. 报表/门禁保留失败和源码变动信息；checksum 只能证明证据未变化，人工证据仍需负责人评审，不能当作不可伪造签名。

## 目标，不是成绩

50 并发用户、30 分钟、约 8:2 读写；1 万商品、10 万订单、1千/5千/1万记工。指定 4核8GB 环境普通读 P95≤500ms、写≤800ms、非预期错误率<0.1%。指定真机冷启动≤3秒、操作反馈约100ms、万笔记工本地保存/筛选 P95≤1秒。RPO≤15分钟、RTO≤2小时，必须通过实际演练。
