# 格式转换交互重构

日期：2026-09-25

## 设计依据

参考实际页面：
- Convertio：https://convertio.co/zh/
- Smallpdf：https://smallpdf.com/cn/pdf-converter
- CloudConvert：https://cloudconvert.com/

采用文件优先、单一主要操作、按需显示设置。去掉大横幅、数字步骤卡片和玻璃装饰。使用微信原生导航栏、白色工作区、紧凑文件行与绿色主按钮。页面底色沿用首页浅绿灰渐变，并降低饱和度。

## 操作路径

1. 文件转换页选择文件；底部弹层选择微信聊天或相册。
2. 显示文件列表，可添加、删除、排序；只提供所有已选文件共同支持的目标格式。
3. 目标格式弹层支持分类和搜索，只显示有可选格式的分类。
4. 视频、文字编码及 PDF 设置在需要时出现，默认折叠。
5. 底部按钮提交；成功进入转换记录；失败保留文件、目标及选项并回到错误位置。
6. 结果使用预览与导出两项操作；导出保留转发、持久保存及临时下载，任务菜单保留取消、重试与删除确认。

文件列表：图片显示本地缩略图，视频优先显示微信返回的封面，聊天视频使用本地视频首帧；格式以小角标显示。文档、表格、压缩包等采用不同的纸张、表格、拉链文件图形，转换记录复用相同组件。没有本地媒体文件的历史记录显示类别图形。

字体、远端配置和转换引擎不在本轮 UI 修改范围。

## 验证

- `node --test packages/ledger-mp/scripts/verify-format-flow.cjs`：11/11 通过。直接执行页面控制器，模拟微信 I/O；覆盖选择来源、图片/视频路径和文档/表格/压缩包类别、公共目标、分类搜索、文件限制、排序提交、失败保留、忙碌保护、设置切换、PDF 参数及菜单分发。
- 开发者工具自带 `wcc` / `wcsc`：新版页面、文件图形组件的 WXML 与 WXSS 编译通过。
- `node packages/ledger-mp/scripts/verify-local-conversions.cjs`：79 种源格式的目标集合与原版一致，共 46 个操作、833 个源目标组合。这是能力集合比对，不能解释为 833 次真实文件转换。
- 本地真实文件转换 19 项成功并下载非空结果：PNG→JPG/WEBP/OCR TXT，TXT→DOCX/EPUB/PDF，DOCX→PDF，CSV→XLSX/PDF，XLSX→CSV，SRT→VTT，PDF→PNG、PDF 分组拆分，ZIP 图片→PDF、两图合成 PDF、合并 PDF，WAV→MP3，MP4→MP3/WEBM。
- 失败任务重试、取消、删除通过。测试创建的任务已清理，用户原有的 2 条任务保留。
- 微信开发者工具已编译显示新版；检查了原生导航、空状态、格式弹层与记录数据。修正原生按钮默认样式挤占文件名及覆盖主按钮样式的问题。开发者工具当前显示 Errors: 0；存在全局骨架组件等既有警告。
- 本轮已在开发者工具打开新版页面及文件来源弹层，并通过系统文件选择器选中合成图片。随后开发者工具弹出自身版本更新窗口，选图后的缩略图没有取得可核对截图；真实手机上的文件选择和分享仍需验收。页面控制器测试不能代替这些原生交互。
- `git diff --check`：通过。
