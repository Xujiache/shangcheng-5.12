# Windows original engine and Linux worker audit

Baseline: repository `9fbe0b94`, pinned source `a7b9b15d32db80cecedae00e89289088656fb1ae`. The published Windows 0.7.10 installer was built from `5d90f84`, according to [REPAIR-0.7.10.md](../../vendor/flyingmouse-format/upstream-a7b9b15/docs/REPAIR-0.7.10.md#L20-L24). Source parity with `a7b9b15` therefore does not prove byte identity with that installer. The catalog declares 46 operations and 1174 source/target pairs; it is not an acceptance count.

The table describes the deployed Linux baseline at audit time. The candidate [Dockerfile](../../packages/server/Dockerfile.conversion-worker) now stages pinned FFmpeg, LibreOffice and Poppler and extracts the Windows OCR models and original docengine. Those changes require an x86-64 image build and conversion output validation before they replace the baseline. The Windows core archive (541,035,233 bytes) was downloaded from the `ci-engines-v1` GitHub release and verified against [ci-engines-v1.json](../../vendor/flyingmouse-format/upstream-a7b9b15/ci-engines-v1.json#L6-L32): SHA-256 `d4f13034e719760790d75569b2dd9696facb88b15b8322f28d2aa4c3dbe6a835`. Selected files and an archive index are cached outside the repository under `/Users/mac/Library/Caches/ledger-flyingmouse-engines/windows-core-audit/`. FFmpeg's exact Windows product build and embedded `pdf2docx` version remain unverified; the embedded PyMuPDF module reports 1.28.2.

Verified Linux acquisition points: [FFmpeg 8.1.1 source](https://ffmpeg.org/releases/ffmpeg-8.1.1.tar.xz) SHA-256 `b6863adde98898f42602017462871b5f6333e65aec803fdd7a6308639c52edf3`; [Poppler 26.05.0 source](https://poppler.freedesktop.org/poppler-26.05.0.tar.xz) SHA-256 `6fef27ff04f37db43054c86bcdff6128c9fb1f6af4ef3c8b369a7e9abd68d0bb`; [LibreOffice 26.2.1.2 Linux x86-64 DEB archive](https://downloadarchive.documentfoundation.org/libreoffice/old/26.2.1.2/deb/x86_64/LibreOffice_26.2.1.2_Linux_x86-64_deb.tar.gz) SHA-256 `9807363c8fabf79fc3562f606ce1673c4b29c3c53baca513f84e762845a093b2` from the official adjacent `.sha256` file. Matching release numbers alone does not establish identical codecs, font substitution or output bytes.

Advanced structure recognition was a definite baseline functional gap. [pdf-structure-engine.js](../../vendor/flyingmouse-format/upstream-a7b9b15/pdf-structure-engine.js#L183-L193) requires a trusted engine and model files, then runs `parse --models … --language ch`; it serializes requests, checks at least 5 GiB free memory and sets bounded OMP/MKL threads ([source](../../vendor/flyingmouse-format/upstream-a7b9b15/pdf-structure-engine.js#L16-L33), [invocation](../../vendor/flyingmouse-format/upstream-a7b9b15/pdf-structure-engine.js#L331-L355)). The deployed Linux image cannot pass this preflight. The candidate stages a Linux engine and SHA-checked models, pending runtime acceptance. Windows' Python 3.11 wheel lock contains PaddleOCR 3.7.0, PaddlePaddle 3.2.2 and PaddleX 3.7.2; Windows wheels and EXE cannot simply be copied into Linux. The existing [macOS launch script](../../packages/server/scripts/start-local-original-conversion.sh#L38-L45) shows how the Python entry point and model directory are injected.

The worker invokes the pinned `server.js` through the loopback [conversion.engine.ts](../../packages/server/src/workers/conversion.engine.ts#L63-L85), but the runtime [patch script](../../scripts/apply-flyingmouse-platform-fixes.cjs#L193-L233) deliberately changes conversion source files. Document the resulting revision and compare output quality, rather than asserting identical source bytes. The 1174 catalog pairs require direct engine, backend and output validation; a green build or declared operation count is insufficient.

The verified Windows `docengine.exe` PyInstaller PYZ contains 55 `pdf2docx` modules. Comparing normalized CPython 3.12 code objects with the public `pdf2docx==0.5.8` wheel found 39 exact matches and 16 differing modules, including `converter`, `RawPage`, table, text and image logic. This proves the public pip wheel alone does not reproduce the Windows docengine. The original `docengine.py` marshal entry is 12,975 bytes with SHA-256 `36404137ad6657f41e10558f7b72de907d845c851c5e9be76e926853d4e99037`; the PYZ is SHA-256 `6f75f22d34ca0cc910ac6bfaf17dcbc639d41a864e816980aa918ddf0b433504`. Both were extracted from the SHA-verified core asset and cached outside the repository.

Windows also packages Thai traineddata and AVS3. Current OCR explicitly fixes `eng+chi_sim` and excludes Thai (`ocr.js:103-105`); the project guidance excludes AV3A and encrypted platform audio from the active input table. These packaging differences are not counted as active functionality defects.
