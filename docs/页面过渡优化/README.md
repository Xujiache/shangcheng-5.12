# 门窗利账 · 全页面过渡与加载优化

## 1. 对齐与范围

- 需求：沿用薄荷绿视觉，统一所有页面跳转时的加载效果，优先轻量、顺畅，不增加人为等待。
- 覆盖：原生 ledger-mp 的全部 41 个已注册页面（36 个主包页面、5 个记工分包页面），包括前进、返回、重定向、底部 Tab、重新进入及鉴权跳转。
- 保留现有 UI、记工生成图标、业务规则、会员边界、本地台账及工程配置。不更换原生技术栈，不修改线上服务，不清理数据，不加入商城 shared 依赖。
- 微信自身的启动画面、胶囊、系统级页面推入动画不属于应用可自定义区域；没有承诺替换这些原生行为。

## 2. 设计与实现

### 轻柔而非拖慢

- 页面只做 220ms 轻淡入（透明度 0.86 → 1），不移动或缩放整页，不额外包裹页面；保留固定页脚、弹层、键盘与画布的布局边界。
- 路由请求立即交给微信，不等待动效完成，也不设置最低加载时长。
- 原生页面尚未准备好时，180ms 后才显示 2px 薄荷色进度提示；1400ms 后补充“正在打开页面…”。快速跳转不会出现一闪而过的提示。
- 进度条是等待反馈，不伪造百分比。页面准备完成、跳转失败或过期反馈结束时清理。10 秒兜底只移除视觉提示，不取消原生操作、不伪造成功。
- 连续相同且无独立回调/事件监听的跳转在途请求合并；保留 Promise 结果、事件通道、回调参数和原生失败信息。带回调/事件的独立请求不擅自丢弃。
- 缓存页面返回不清空业务数据或主动修改滚动位置；应用单纯切回前台不重复播放入场动画。

### 有内容结构的等待占位

- `lz-skeleton` 提供列表、概览、详情、表单、追加加载五种占位布局。
- 16 个联网页面共 18 处加载位置接入：主页、订单、经营报表、客户列表/详情/编辑、订单详情/编辑、成本分析/分类、下料、会员、目标、邀请、消息、更新日志。
- 纯本机工具、记工本地台账及即时可用表单直接展示，不人为加骨架或等待。已有内容继续使用原来的后台刷新行为。
- 流光被限制在圆角占位卡内，不照亮卡片间的空白；隐藏页面停止流光，避免后台无用动画。
- 订单/客户编辑新增明确的读取状态：资料就绪前隐藏保存入口并在保存方法中设防；失败可重试，不允许空表单覆盖原记录。

### 性能与可选择性

- `MotionPage` 是显式的 Page 包装，不覆盖全局 Page/wx。原生命周期参数、返回值、异步结果和异常保持传递。
- 动效只使用 CSS；没有逐帧 `setData`。离场页面不接收路由计时器更新，重复组件生命周期不重复写相同动效状态。
- “外观与个性化 → 页面过渡 → 轻柔页面动效”可关闭新增淡入和流光；同时提供系统减少动态效果的样式兜底。
- 记工分包预下载：首页仅 Wi-Fi 预取，进入记工总览后允许当前网络预取。它只加载代码资源，不上传台账；仍保留按需注入组件。配置依据[微信官方分包预下载说明](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/preload.html)，实际预下载命中需原生运行环境确认。

## 5. 仍需原生环境验收

本次没有完成开发者工具自动化运行截图、真机帧率/耗时测量、iOS/Android 安全区及键盘实测，也没有重新确认此前无调用栈的渲染层 `length` 错误。不能将上述静态编译或浏览器样式预览视为这些问题已通过。

建议在微信开发者工具和至少一台 iOS/Android 真机逐项验证：

1. 首页 → 四个工具 → 返回；底部 Tab 连续切换，留意有无白闪、重复打开和固定按钮漂移。
2. 记工五个页签互相进入，检查分包首次/再次打开；本地断网仍直接可用，不出现为了动画而添加的等待。
3. 模拟弱网进入客户/订单详情与编辑，看到占位后加载完成；失败重试仍可用，未读到原记录时不能保存。
4. 先滚动再进入详情并返回，核对位置和输入保留；刷新继续使用原业务逻辑。
5. 动画期间返回、切后台、重复点同一入口；确认没有常驻进度提示和销毁页面写入报错。
6. 关闭“轻柔页面动效”后检查淡入/流光消失；弱网提示仍可读，原功能不受影响。

## 6. 维护与回退

后续新增页面应使用 `MotionPage`、`navigation` 并沿用根 view 动效类和独立路由反馈组件，新增网络读取再按真实内容选择骨架类型。不要把加载效果写成业务请求必须等待的动画 Promise。

需要降低动效时优先使用外观开关；工程回退只撤销本次页面过渡相关差异。当前工作区还包含既有记工系统与图标改动，不要全仓 reset、清理未跟踪文件或覆盖 `project.config.json`。
